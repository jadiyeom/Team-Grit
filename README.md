# Team-Grit Studio

**Turn an idea into a visual explanation.** Team-Grit is evolving from a set of algorithm demos into an AI-powered Manim storytelling studio: describe a concept, generate a storyboard and custom Manim Community Edition scene, then render and preview the animation.

## Current capabilities

- Natural-language prompt workspace with starter ideas.
- Storyboard and Manim Python code generated by a configured LLM.
- Provider/mode configuration for OpenAI, Anthropic, Google Gemini, OpenAI-compatible endpoints, and local inference endpoints through LiteLLM.
- Auto, Quality, Fast, Local, and Custom API modes.
- Audience, duration, aspect ratio, and visual-style controls.
- Project history stored locally as JSON.
- Scene-by-scene narration script and SRT caption text generated from storyboard timings.
- Docker-based render endpoint with network disabled, memory/CPU/PID limits, read-only container root, and a render timeout.
- Responsive frontend with generated-code inspection and copy controls.

**Important current limitation:** narration text and caption timing are implemented, but text-to-speech audio generation, accurate speech/audio synchronization, background music, user authentication, persistent cloud storage, and a true asynchronous job queue are not implemented yet. Treat this as an early MVP, not a production-hosted service. API keys entered in the request are not persisted, but should only be used on a trusted private instance.

## Quick start

Requirements:
- Python 3.11+ (Python 3.12 recommended)
- A configured LLM API key or a running OpenAI-compatible local endpoint
- Docker Desktop / Docker Engine for isolated Manim rendering

### 1. Install

```bash
git clone https://github.com/jadiyeom/Team-Grit.git
cd Team-Grit
python -m venv .venv
```

Activate the virtual environment:

Windows PowerShell:
```powershell
.venv\Scripts\Activate.ps1
```

macOS / Linux:
```bash
source .venv/bin/activate
```

Install dependencies and configure environment:
```bash
pip install -r requirements.txt
```

Copy `.env.example` to `.env` and add a key for the provider you intend to use. Never commit `.env` or API keys.

### 2. Run

```bash
uvicorn app:app --reload
```

Open http://127.0.0.1:8000. API documentation is available at http://127.0.0.1:8000/docs.

### 3. Generate and render

1. Enter an idea or select a starter prompt.
2. Choose a mode/provider, audience, duration, style, and aspect ratio.
3. Generate the storyboard and Manim source.
4. Review the generated scene and narration script.
5. Select **Render video**. The backend invokes Docker to run the generated scene in a disposable, network-disabled container.
6. Preview the resulting MP4 in the workspace.

The first render may take longer while Docker downloads the Manim image.

### Model catalog (checked October 9, 2026)

The UI's **Model ID** field offers these suggested IDs while still allowing any model ID supported by your provider. Availability depends on your account, region, API access, and the installed LiteLLM version. A catalog entry is a suggestion, not a live guarantee that your key can call it.

| Provider | Suggested model IDs | Recommended use |
|---|---|---|
| OpenAI | `gpt-6-astra`, `gpt-6.1-sol`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` | Astra for hardest story/code generation; Sol for balanced quality; Luna for lower-cost high-volume work |
| Anthropic | `anthropic/claude-fable-5`, `anthropic/claude-opus-5`, `anthropic/claude-opus-4-8`, `anthropic/claude-sonnet-5`, `anthropic/claude-haiku-4-5` | Fable/Opus for complex animation planning and code; Sonnet for balance; Haiku for speed |
| Google Gemini | `gemini/gemini-3.8-flash`, `gemini/gemini-3.1-pro-preview`, `gemini/gemini-3.7-flash` | Flash for fast generation; Pro preview for harder reasoning and coding |
| OpenAI-compatible | Provider-specific model ID, e.g. `openai-compatible/model` | Any compatible chat-completions endpoint |
| Local | Provider-specific model ID, e.g. `openai/local-model` | Ollama or another OpenAI-compatible local inference server |

Official references: [OpenAI model catalog](https://developers.openai.com/api/docs/models), [Anthropic model overview](https://platform.claude.com/docs/en/about-claude/models/whats-new-claude-4-5), and [Gemini API models](https://ai.google.dev/gemini-api/docs/models).

The default OpenAI model is `gpt-6-luna`; Fast uses `gpt-6-luna` and Quality uses `gpt-6.1-sol`. Override these with `OPENAI_MODEL`, `TEAMGRIT_FAST_MODEL`, and `TEAMGRIT_QUALITY_MODEL`. Model IDs and availability change; verify them in your provider's current API catalog before production use. LiteLLM may require a provider prefix such as `anthropic/` or `gemini/`.

Provider selection is not a guarantee that a model is enabled for your account or that credentials have sufficient quota. The API reports a clear error if configuration is missing or a provider request fails.

Request-level settings can override the model, base URL, and API key for one generation request. Those values are not written to the project file. Avoid using request-level keys on a publicly exposed instance without authentication and rate limiting.

### Modes

- **Auto:** uses `TEAMGRIT_DEFAULT_PROVIDER`.
- **Fast:** uses `TEAMGRIT_FAST_MODEL` or falls back to the configured OpenAI model default.
- **Quality:** uses `TEAMGRIT_QUALITY_MODEL` or the configured OpenAI model default.
- **Local:** uses the configured local endpoint.
- **Custom API:** uses a custom OpenAI-compatible base URL and model.

Set `TEAMGRIT_FAST_MODEL` and `TEAMGRIT_QUALITY_MODEL` to model identifiers supported by the provider you have selected. Mode defaults are a convenience, not an automatic model benchmark.

## API

Interactive OpenAPI documentation: `/docs`.

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/v1/health` | Health check |
| GET | `/api/v1/providers` | Available modes and provider configuration status |
| POST | `/api/v1/projects` | Generate storyboard and Manim source from a prompt |
| GET | `/api/v1/projects` | List recent local projects |
| GET | `/api/v1/projects/{project_id}` | Retrieve a project |
| GET | `/api/v1/projects/{project_id}/code` | Retrieve generated Python source |
| GET | `/api/v1/projects/{project_id}/narration` | Retrieve scene narration script |
| GET | `/api/v1/projects/{project_id}/captions` | Retrieve generated SRT text |
| POST | `/api/v1/projects/{project_id}/renders` | Render the project |
| GET | `/api/v1/renders/{render_id}/video` | Retrieve a completed MP4 |

Example generation request:

```json
{
  "prompt": "Explain gradient descent with a moving point on a loss curve.",
  "mode": "auto",
  "audience": "beginner",
  "duration_seconds": 60,
  "aspect_ratio": "16:9",
  "style": "minimal",
  "narration": true
}
```

## Security and deployment notes

Generated Manim source is executable Python. The render endpoint therefore requires Docker and runs code inside a container with networking disabled and resource limits. This is defense in depth, not a guarantee that hostile code is harmless. Do not expose this early MVP to untrusted users on a public network.

Before public deployment, add authentication/authorization, per-user project isolation, request and render rate limits, a dedicated restricted worker service, artifact access controls, persistent storage, asynchronous render jobs, operational monitoring, and a security review. The API server itself is not designed to be run with privileged access. Do not mount the Docker socket into a public multi-tenant API container.

The provided Dockerfile packages the API dependencies but does not configure a secure Docker socket/worker arrangement. For local development, run the API directly on the host and let it invoke your installed Docker CLI. Do not assume the Dockerfile alone is a production deployment.

## Tests

```bash
pytest
```

Tests use the FastAPI test client and do not make paid LLM calls. A full generation/render integration test requires provider credentials and Docker.

## Roadmap

1. Add robust provider-aware structured outputs and iterative render-error repair.
2. Add true text-to-speech integrations and align narration audio to scene timings.
3. Move renders into a queued worker with cancellation and progress reporting.
4. Add secure authentication, project ownership, and storage abstraction.
5. Add scene editing/regeneration and high-quality exports for landscape and vertical formats.
6. Add end-to-end tests that render a small known Manim scene.

## Legacy algorithm examples

The original sorting, searching, and linked-list scripts remain in the repository as historical examples. The studio's goal is broader: use an LLM to create new visual explanations from a user's own prompt, rather than restricting the experience to a predefined algorithm catalogue.
